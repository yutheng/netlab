What I learned

Where are the data, control and management planes in your network?

Data plane and control plane - switch, management plane - mininet

How did your switches learn which port leads to each host? Use your MAC table evidence.

For not local, through source MAC, for example mac 01 is learned on port 1 means h1 is connected to this port. While for lcoal, it means that the port mac address is belongs to the switch itself.

Which of the four kinds of programmability is this assignment (a network described as data, then built and documented by scripts)? Why isn't it any of the other three?

This lab uses configuration as data / declarative modeling, defining the desired end-state of the network entirely as data and compiling or rendering them to automatically build and provision the environment because we are not using script to log into the devices, API and controller

Week 1's 2 a.m. change on 40 switches: what would be different if those switches were described like your network?

Instead of manually configuring the switches using the CLI one by one, they could be managed the switches by updating the template and redeploy

What's the difference between your network's data model and its serialisation? Use YAML and JSON as the example.

Data model is the underlying logical structure like hosts, switches and links. Serialization is the text format used to store or transmit the data. YAML is a more human readable format that use spaces to show hierarchy and nesting while JSON use braces and quotes

Why is it better to catch bad data in check() than with pingall? What did IPv6 notice about a duplicate address that IPv4 didn't?

Catching errors with check() happen before building the network, saving time and preventing invalid stated. IPv6 uses DAD to check whether the host IP address is duplicated while IPv4 blindly accept duplicate IPs

What does your Git history give you that copying files into folders named topology-v2-final wouldn't?

Git tracks line-by-line diffs, allows to roll back safely, branch out, and provides a clear audit history of why and when changes happened
